# html-report

목표는 단순하다 — **매번 같은 포맷·같은 품질의 HTML 보고서를 낸다.** 도메인이 무엇이든 디자인은 일정해야 한다.

이 스킬의 핵심 자산은 검증된 **템플릿 하나**다: `assets/template.html`.
**디자인을 새로 짜지 마라.** 템플릿에서 시작해 내용만 채운다. 그래야 일관성과 품질이 보장된다.

산문(문장·단락)은 별도 스킬 **`structured-writing`** 의 원칙으로 쓴다: 한 단위 한 메시지, 대조('A가 아니라 B'), 쉽지만 정확한 말, 군더더기 제거.

---

## 워크플로

### 1. 내용을 먼저 구조화한다 (structured-writing)
디자인보다 *논지*가 먼저다. 글 전체의 '한 문장'을 정하고, **점진적 공개** 구조로 배치한다 — 위에서 멈춰도 가치가 남도록:
> 표지 + 한 줄 결론 → 본론(분석·근거) → 핵심 요약·시사점 → 부록(출처·신뢰도)

각 섹션은 하나의 메시지가 지배하게 하고, 핵심 문장은 `.core`로 강조한다.

### 2. 템플릿에서 시작한다
`assets/template.html`을 출력 경로로 복사한 뒤 내용을 채운다.
**`<style>`·라이트박스 `<script>`·print 규칙은 그대로 둔다** (검증된 값). 색·여백·타이포를 임의로 바꾸지 않는다.
목차(`nav.toc`)의 링크와 각 `section`의 `id`를 일치시킨다.

### 3. 컴포넌트를 골라 채운다
| 컴포넌트 | 언제 | 비고 |
|---|---|---|
| `.verdict` | 글 전체의 '한 줄 결론' | 표지 직후 또는 결론 장 |
| `.eyebrow`+`h2`+`.lead` | 모든 섹션의 머리 | 번호+라벨 |
| `.subhead` | 한 섹션을 소파트로 | 2-A/2-B 식 |
| `.theme` + `.core` | 관통 주제·논점 | **핵심 한 줄(.core)이 주인공**, 부연은 칩으로 |
| `.chips` | 근거·출처를 압축 | 본문 곁가지를 강등 |
| `details.s` | 세션·항목 상세 | 요약은 summary, 상세는 펼침 |
| `figure.slide` | 중요한 사진·도식 | **클릭→모달 확대 + 스크롤 줌**(자동·필수) |
| `ol.keys` | 번호 매긴 핵심 결론 | |
| `.imp` | 매핑·시사점·제안 | `area`=범주 태그 |
| `.call` / `.call.endo` | 강조 콜아웃 | `.endo`=앰버(주의·'우리 관점') |
| `table` / `.method` | 부록(데이터·출처·방법) | |
| **`figure.diagram` + SVG** | 관계·흐름 도식(허브-스포크·계층 flow) | 사진(`figure.slide`)이 아닌 *도식* — 글로 설명 말고 그림으로 |
| **`.tl` 인터랙티브 타임라인** | 로드맵·일정 | `details` 기반 — 막대 행 클릭 시 하위 Task 펼침 |
| **`.silos`/`.pillars`/`.tracks`** | 구조 시각 블록 | 분절(사일로)·N개 핵심요지(pillar)·2~3축 대비(track) |

세부 마크업은 `assets/template.html`의 주석을 그대로 따른다.

> **시각화 우선.** 구조·흐름·스케줄은 문장·표로는 ‘한눈에’가 안 된다 — 허브/흐름은 **SVG 도식(`figure.diagram`)**, 로드맵은 **인터랙티브 타임라인(`.tl`)**, 비교·분절은 **구조 카드(`.silos`/`.pillars`/`.tracks`)**로. SVG 관습: viewBox를 `--col`(760)에 맞추고 · 폰트는 SVG 내부 `<style>`로 Pretendard · 색은 팔레트 hex · 좌표는 단순히. 손으로 짠 SVG는 깨지기 쉬우니 template 예제를 복제해 값만 바꿔라.

### 4. 이미지는 넣고 → 인라인한다
- 이미지를 출력물 옆 `assets/`에 두고 `figure.slide > img`의 `src`로 건다.
- **클릭 확대는 필수.** 모든 이미지는 `figure.slide`로 감싸거나 `class="zoomable"`을 줘, 클릭하면 모달로 확대되고 스크롤로 줌이 되게 한다(템플릿이 자동 처리). 그냥 `<img>`만 덩그러니 두지 말 것.
- **회전 주의:** 휴대폰 사진은 EXIF 방향 정보가 있고, 리사이즈하면 그 정보가 사라져 *눕는* 경우가 있다. 미리보기에서 똑바로 보여도, 의심되면 픽셀을 실제로 회전(보통 CW 90°)해 저장하라.
- 다 걸었으면 **단일 파일로 만든다:**
  ```bash
  python scripts/inline_images.py <보고서.html>
  ```
  로컬 `<img>`가 base64로 인라인돼 파일 하나만 공유해도 이미지가 보인다.

### 5. 렌더를 검증한다
브라우저로 열어 확인한다. 헤드리스로 점검할 때(Windows 기준 실전 팁):
- `chrome --headless --screenshot=out.png --window-size=1320,4000 "file:///..."` — *classic* `--headless`가 안정적이다.
- 출력 PNG는 **쓰기 가능한 경로**(예: TEMP)로. 한 번에 캡처 가능한 높이는 ~8000px 한계.
- `<details>`는 기본 닫힘이라 캡처에 안 나온다. 펼친 상태를 보려면 임시 사본에 `open`을 넣어 캡처.
- **헤드리스가 없거나 막히면**(예: `pdftoppm`/chrome 부재) — 파일을 사용자에게 직접 전달(SendUserFile)해 브라우저로 확인받고, *편집한 섹션을 다시 읽어* 구조를 자체점검한다. 손으로 짠 SVG·새 컴포넌트는 특히 한 번 더 본다.

## 기존 보고서를 고칠 때 (반복 수정)

한 파일을 여러 번 다듬는 일이 잦다. **검증된 골격을 깨지 않는 게 핵심:**
- **`<style>`·라이트박스 `<script>`는 절대 손대지 마라.** `<body>`의 내용만 고친다.
- 작은 수정은 **섹션 안의 연속 블록**을 교체한다(빈 줄을 걸치면 매칭이 어긋난다). 큰 개편은 **`<section>`을 통째로** 교체.
- 표지 한 줄 결론(`.verdict`)은 내용이 진화하면 **함께 갱신**해, 첫 화면 결론이 본문과 어긋나지 않게.
- 수정 뒤엔 **렌더 검증**(위 5번)으로 닫는다.

## 지킬 디자인 원칙 (왜 이렇게 두는가)

- **절제된 팔레트 + 넉넉한 여백.** 잉크 네이비 + 인디고 액센트 + 앰버(주의) 한 점. 장식보다 위계로 읽히게.
- **점진적 공개.** 결론을 위에, 근거를 아래에, 상세를 펼침으로. 바쁜 의사결정자가 어디서 멈춰도 가치가 남는다.
- **한 섹션 한 메시지, 핵심은 `.core`로.** 시선이 한 줄에 먼저 꽂혀야 메시지가 전달된다.
- **관계·흐름·일정은 그림으로.** 구조·스케줄은 문장·표로는 한눈에 안 들어온다 — SVG 도식·인터랙티브 타임라인·구조 카드로 보여주고 글은 줄인다(워크플로 3 참고).
- **모든 이미지는 클릭 → 모달 확대 + 스크롤 줌. 예외 없음.** 이미지는 `figure.slide`로 감싸거나 `img`에 `class="zoomable"`을 준다 — 그러면 템플릿 내장 라이트박스가 클릭 확대·스크롤 줌·드래그·더블클릭 초기화·ESC 닫기를 자동으로 건다. 라이트박스 `<script>`는 **절대 제거하지 말 것**(모든 보고서 공통 사항).
- **단일 자체완결 파일.** 외부 의존 없이 어디서나 열린다(폰트 CDN 제외, 오프라인은 시스템 폰트로 폴백).
- **print·반응형·접근성.** 시맨틱 태그, 충분한 대비, 키보드 이동(목차 링크). 인쇄 시 목차 숨김·카드 펼침.
- **한국어 최적화.** Pretendard, `word-break:keep-all`.

## 신뢰도 (보고서의 신뢰를 지키는 선)

- 외부 수치·인용·자동 전사 기반 내용은 **출처와 검증 여부를 밝힌다.** 부록 `.method`에 한 줄이라도.
- 자동 요약·전사가 전문용어를 왜곡할 수 있으니, 핵심 용어는 표준 의미로 검증 후 쓴다.
- 모르면 비운다. 메타·수치를 억지로 채우지 않는다.

## 함께 쓰는 것

- **structured-writing** — 문장·단락 구성(핵심 문장·대조·쉬운 말·군더더기 제거). 이 스킬은 '담는 그릇', structured-writing은 '쓰는 법'.
- `assets/template.html` — 시작점(디자인 시스템 + 컴포넌트 + 라이트박스).
- `scripts/inline_images.py` — 이미지 base64 인라인 → 단일 파일.
