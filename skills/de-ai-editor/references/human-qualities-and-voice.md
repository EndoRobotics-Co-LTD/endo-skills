> 이 파일은 상세 사전/예시다. 확정 운영규칙·가드레일은 상위 `SKILL.md`가 우선한다.
> 특히 SKILL.md가 override 하는 것:
> 1. 정량 임계치(cv·%·문단당 N개)는 방향 참고일 뿐 **추종 금지** — 판정은 낭독 테스트로 한다(수치 목표를 좇으면 인공 burstiness라는 새 AI 티가 생긴다).
> 2. 원문에 없는 **수치·고유명사·건수 창작 금지** — 복구 가능한 것만 넣고, 없으면 `[근거/수치 필요]` flag(의료기기 데이터 무결성).
> 3. **단일 출현은 감점 아님** — 군집·빈도·저버스티니스일 때만 신호(em-dash·삼단나열·번역투 단독 판정 금지).

# de-ai-editor 스킬 설계 — 사람 글의 특질 + 문체 지문 추출 스펙

한국어 비즈니스/보고서 레지스터 1순위. 영어 병행 규칙은 각 표에 표시. 저자 위조가 아니라 가독성·신뢰도 향상이 목적이므로, 사실·수치·주장은 원문 보존하고 **표현 층만** 손댄다.

---

## 0. 스킬 위치와 4패스 파이프라인

`structured-writing`(이미 보유)과 겹치지 않게 분업한다. 그 스킬은 **논지·구조**(핵심 메시지, 대조, 강등)를 잡고, `de-ai-editor`는 그 위에서 **문체를 사람 것으로** 되돌린다. 순서상 구조 → 문체다.

| 패스 | 하는 일 | 산출 |
|---|---|---|
| ① 탐지(Detect) | 문단 단위로 AI 티 마킹 (§3 사전 기준) | 밑줄+태그된 초안 |
| ② 진단(Diagnose) | 태그별로 "왜 AI 같은가" 1줄 + 어느 특질(§1) 결핍인지 | 진단표 |
| ③ 재작성(Rewrite) | §1 특질 규칙 + (있으면) §2 문체 지문 파라미터를 제약으로 걸고 고쳐씀. **사실 불변** | 개정안 |
| ④ 적대적 재검증(Adversarial) | "이거 아직 AI가 쓴 티 나나?"를 적으로 채점. 통과 못 하면 ③으로 반송 | 점수+합격/반송 |

문체 지문 층은 이번 범위 밖 → ③·④에 **슬롯**만 남긴다(§2의 `voice_profile`). 지문이 없으면 §1 일반 기준으로만 돌아가고, 있으면 개인화 제약이 얹힌다.

## 1. 과제 1 — 사람 글의 적극적 특질

"AI 티 제거"는 뺄셈, 이건 덧셈이다. 밋밋하고 매끄러운 글에 **마찰·입장·비대칭**을 넣는다. 각 특질에 결핍 신호(이게 없으면 AI다)와 계량 기준을 붙였다.

| # | 특질 | AI 결핍 신호 | 실행 규칙 | 계량 기준 |
|---|---|---|---|---|
| 1 | **문장 길이 편차** (짧게 치고 길게 풀기) | 문장이 죄다 40~60자에 몰림, 리듬 없음 | 강조는 단문으로 독립시키고, 부연은 한 문장에 몰아 길게 | 문단마다 단문(≤12자/어절 3개) 최소 1회. 문장길이 변동계수(표준편차÷평균) ≥ 0.5 |
| 2 | **입장 먼저 → 근거 나중** | "~한 측면도 있고 ~한 측면도 있다" 양비론, 결론 유예 | 섹션·문단 첫 문장에 판단을 박는다. 근거는 그 뒤 | 문단 첫 문장이 주장/판단인 비율 ≥ 70%. "~라고 볼 수 있다" 완충 종결 문단당 ≤1 |
| 3 | **구체**(숫자·고유명사·현장 일화) | "효율성 향상", "다양한 이해관계자", "여러 부서" 같은 추상 명사로 도망 | 추상 주장 뒤 한 호흡 안에 구체 근거. 실명·수치·날짜·건수 | 추상 주장당 구체 앵커 1개. "다양한/여러/각종" → 실제 개수·이름으로 치환 |
| 4 | **능동·직설** | 피동·명사화("~가 요구된다", "개선을 도모/진행/수행") | 주어를 세우고 동사를 살린다. "우리가 고친다", "고쳐야 한다" | 피동 표현 문단당 ≤1. 공허 동사(진행·수행·도모·실시)+명사 → 본동사로 |
| 5 | **절제된 장식** | 형용사 3연발, "매우/정말/굉장히/효과적으로", 볼드·이모지 남발 | 강조는 부사·볼드가 아니라 문장 구조(단문화·도치)로 | 강조 부사 문단당 ≤1. 이모지 0. 볼드는 진짜 결론 문장에만 |
| 6 | **자기 어휘·현장 용어** | 무난한 표준어로 순화됨, 조직 은어 소거 | 도메인 용어는 원형 유지. 순화 금지 | 반려·공번·허가단위·하드카피·개발의뢰서·DHF·ECR 등 원형 보존. 일반어 치환 시 플래그 |
| 7 | **리듬·강약(강등)** | 모든 문장이 동등한 비중, 부연이 본론과 같은 무게 | 결론은 짧게 독립, 부연·전제는 괄호·짧은 종속절로 강등 | 한 문단 = 한 주장. 부연은 주절 앞이 아니라 뒤/괄호로 |
| 8 | **뻔한 것 생략**(독자 지능 신뢰) | 정의부터 시작("PLM이란~"), 결론 반복("결론적으로~"), 자명한 전제 나열 | 대상 독자가 이미 아는 것 삭제. 요약의 요약 삭제 | 임원·동료 대상 문서에서 용어 정의·배경 재설명 삭제. "~라는 점에서 중요하다" 삭제 |
| 9 | **종결·연결 다양성**(한국어 특화) | "~습니다" 3연속, "또한/특히/따라서/즉" 남발 | 종결어미 섞기, 접속부사 최소화(문장 관계로 대체) | 동일 종결어미 3연속 금지. 접속부사 문단당 ≤1 |
| 10 | **대조로 날 세우기** | 평면 나열("A하고 B하고 C한다") | 핵심은 "A가 아니라 B" 구문으로 | 섹션당 대조 구문 최소 1회(단, 남용 금지) |

*영어 병행:* 1(burstiness)·2(stance-first)·3(concreteness)·4(active voice)·8(cut the obvious)은 그대로 적용. 9는 종결어미 대신 문장 시작 다양성("This/It/There is" 반복 금지)과 transition word 절제로 치환.

### Before / After (그의 실제 도메인으로)

**개발의뢰서 서두**
- AI: "본 개발의뢰서는 신규 어댑터 제품의 개발을 위한 다양한 요구사항을 체계적으로 정리하고, 이해관계자 간의 원활한 소통을 도모하기 위해 작성되었습니다."
- 사람: "290 스코프용 어댑터를 새로 만든다. 이 문서엔 착수 전에 합의할 것만 담았다. 나머지는 뺐다." *(특질 1·3·8)*

**임원 보고**
- AI: "PLM 시스템 구축은 조직의 데이터 관리 효율성을 크게 향상시킬 수 있는 매우 중요한 이니셔티브이며, 다양한 부서의 협업이 필수적입니다."
- 사람: "PLM부터 사면 순서가 틀린다. 프로세스와 산출물 정의가 없는 상태에서 시스템을 깔면 RQA가 또 반려한다. 정의가 먼저다." *(특질 2·3·5·10)*

**메일**
- AI: "안녕하세요. 항상 노고에 감사드립니다. 다름이 아니라 BOM 관련하여 몇 가지 확인이 필요한 사항이 있어 연락드립니다."
- 사람: "김은정님, BOM 두 가지만 확인 부탁드립니다." *(특질 5·8)*

## 2. 과제 2 — 문체 지문(Voice Fingerprint) 추출 스펙

목표: 박동진 본인 글 1~2개에서 측정 가능한 것만 뽑아 **파라미터 카드**로 만들고, ③ 재작성·④ 재검증이 이걸 제약으로 읽게 한다. 표본이 작으므로 **안정적인 차원은 값으로, 불안정한 차원은 넓은 밴드로** 저장하고 신뢰도를 함께 기록한다.

### 2.1 지문 카드 스키마 (스킬이 읽는 슬롯)

```yaml
voice_profile:            # 없으면 §1 일반 기준만 적용
  meta: { samples: 2, register: "report", confidence_note: "..." }
  sentence_len:  { mean: 46, cv: 0.55, short_ratio: 0.18, conf: mid }   # 글자 기준
  paragraph:     { sents_per_para: 3.2, one_claim_per_para: true, conf: mid }
  endings:       { primary: "평서-다", secondary: "음슴체", forbid_run: 3, conf: high }
  lexicon:       { signature: ["반려","정의가 먼저","순서가 틀린다"], conf: low }
  connectives:   { allow: ["그런데","다만"], cap_per_para: 1, avoid: ["또한","즉","따라서"], conf: high }
  punctuation:   { comma_density: low, dash: "em—aside", paren: "frequent", ellipsis: no, conf: high }
  formality:     { level: "음슴체+평서 혼합", honorific: "메일만 해요체", conf: high }
  structure:     { bullet_vs_prose: "bullet-lead+prose", bullet_ratio: 0.4, conf: high }
  emphasis:      { method: ["단문독립","대조구문"], bold: rare, conf: mid }
  jargon:        { preserve: ["공번","허가단위","하드카피","DHF","ECR","mBOM"], conf: high }
```

### 2.2 추출 절차 (경량, 1~2 샘플)

1. **샘플 고르기**: 같은 레지스터 1~2개(보고서면 보고서, 메일이면 메일). 레지스터가 섞이면 카드를 분리(`report` / `email`).
2. **정규화**: 인용문·표·붙여넣은 남의 글 제거(본인 문장만).
3. **측정**: 아래 표대로. 손으로 훑어도 되고, 20줄짜리 파이썬(문장 분리 → 글자수/종결어미/구두점 카운트)이면 충분. 통계 차원은 값보다 **밴드**로 잡는다.
4. **신뢰도 태깅**: N=1~2에서 안정적인지(§2.3의 conf) 표시. `low`는 참고용, 강제하지 않는다.
5. **카드 저장 → 슬롯 주입**: 이후 세션에서 이 카드를 읽어 ③·④에 제약으로 건다.

### 2.3 차원별 스펙 (측정법 → 산출 파라미터 → 편집 반영)

| 차원 | 샘플에서 뽑는 법 (1~2개로) | 산출 파라미터 | 편집에 반영하는 법 | N=1~2 신뢰도 |
|---|---|---|---|---|
| 평균/편차 문장 길이 | 문장별 글자수 → 평균, 변동계수(표준편차÷평균), 단문(≤12자) 비율 | mean, cv, short_ratio | 재작성 후 cv가 카드 밴드에 들도록. 단문 비율 못 맞추면 긴 문장 하나를 둘로 쪼갬 | 중 (넓은 밴드로) |
| 문단 길이 | 문단당 문장 수·글자 수 | sents_per_para | 문단을 그 크기로 재청킹. "한 문단 한 주장" 유지 | 중 |
| 종결어미 패턴 | 종결어미 빈도표: 평서-다 / 음슴체(~함·~음·명사형) / 해요체 / 하십시오체 | primary, secondary, forbid_run | 우세 어미로 통일하되 secondary를 리듬용으로 섞음. 동일 어미 연속 상한 적용 | **높음** |
| 즐겨 쓰는 어휘 | 불용어 뺀 빈출 내용어 + 반복되는 표현구(시그니처 문구) | signature[] | 화이트리스트로 우선 채택. 동의어로 밋밋하게 바꾸지 않음 | 낮음 (시그니처 문구만 신뢰) |
| 접속·전이 습관 | 접속부사 종류·빈도, 문장 잇는 방식 | allow[], avoid[], cap | 그가 안 쓰는 접속부사("또한/즉/따라서") 삽입 금지. 그가 쓰는 것만 소량 허용 | **높음** |
| 구두점 습관 | 쉼표 밀도, 대시(—/-) 용법, 괄호 빈도, 말줄임·콜론·세미콜론 유무 | punctuation profile | 그의 괄호·대시 방식으로 부연을 강등. 그가 안 쓰는 세미콜론·말줄임 주입 금지 | **높음** |
| 격식 수준 | 존대 등급, 한자어 vs 고유어 비율(대략), 레지스터별 차이 | level, honorific | 레지스터별로 락. 메일=해요체, 보고=음슴체/평서 등 카드대로 고정 | **높음** |
| 불릿 vs 산문 | 전체 줄 중 불릿 줄 비율, "불릿 리드 후 산문" 같은 패턴 | bullet_ratio, pattern | 그 비율에 맞춰 구조화. 산문가면 불릿 강제 안 함(그 반대도) | **높음** |
| 대시/괄호 습관 | 인라인 부연을 대시로 처리하는지 괄호로 처리하는지 | aside_style | 강등을 그 스타일로 통일 | 높음 |
| 강조 방식 | 볼드/따옴표/어순 도치/반복/단문독립 중 무엇으로 강조하나 | emphasis method[] | 볼드 남발 대신 그의 강조 수단으로 치환 | 중 |
| 은어/전문어 | 샘플에 나온 도메인 용어를 용어집으로 수집 | preserve[] | 이 목록은 절대 순화 금지. §1-6 규칙과 연동 | **높음** |

*경량 원칙:* `high`(종결어미·접속·구두점·격식·불릿·은어)는 값으로 강제, `mid`(문장/문단 길이·강조)는 밴드로 유도, `low`(어휘 통계)는 시그니처 문구만 남기고 나머지는 버린다. 표본 늘면 `low`부터 승격.

*영어 병행:* 종결어미 → 문장 시작 패턴·대명사 습관, 한자어 비율 → 라틴어계 대 앵글로색슨계 어휘 톤, 나머지(문장길이·구두점·불릿·강조·jargon)는 동일 축.

## 3. (보조) 한국어 AI 티 탐지 사전 + 적대적 재검증

①·④가 쓸 실측 기준. 과제 1·2가 "덧셈"이라면 이건 "뺄셈" 목록이다.

### 3.1 한국어 AI 티 사전 (탐지 → 태그)

| 태그 | 신호(정규식/키워드로 잡힘) | 연결 특질 |
|---|---|---|
| `hedge` | ~라고 할 수 있다 / ~인 것으로 보인다 / ~할 수 있습니다 남발 | 2 |
| `balance` | ~한 측면도 있고 ~한 측면도 / 양비론, 무입장 | 2 |
| `abstract` | 효율성·최적화·다양한·여러·각종·전반적 | 3 |
| `nominalize` | 개선을 도모/진행/수행/실시, ~의 향상 | 4 |
| `passive` | ~가 요구된다 / ~될 필요가 있다 | 4 |
| `filler-adv` | 매우·정말·굉장히·효과적으로·성공적으로 | 5 |
| `triad` | 강박적 3요소 나열(A하고 B하며 C한다) | 1·10 |
| `connective-spam` | 또한·특히·즉·따라서·나아가 반복 | 9 |
| `ending-mono` | 동일 종결어미 3연속 | 9 |
| `translationese` | ~을 통해 / ~에 있어서 / ~함에 있어 | 4·6 |
| `obvious` | 결론적으로 / ~란 …입니다 정의 / 요약 반복 | 8 |
| `deco` | 이모지, 볼드 남발, 제목마다 감탄 | 5 |
| `boilerplate` | "다름이 아니라", "노고에 감사", 상투 인사 과다 | 5·8 |

### 3.2 적대적 재검증 루브릭 (④)

각 항목 0~2점(0=여전히 AI, 2=사람). 아래 게이트로 판정.

| 항목 | 2점 기준 |
|---|---|
| 리듬 | 단문·장문 섞임, 문단당 단문 1회 이상 |
| 입장 | 문단 첫 문장에 판단이 박혀 있음 |
| 구체 | 추상 주장마다 수치·실명 앵커 존재 |
| 능동 | 피동·공허동사 거의 없음 |
| 절제 | 강조 부사·볼드·이모지 최소 |
| 종결/연결 | 어미 다양, 접속부사 문단당 ≤1 |
| 뻔함 제거 | 정의·요약 반복·자명한 전제 없음 |
| **지문 일치**(카드 있을 때) | 종결어미·구두점·격식·불릿 비율이 카드 밴드 안 |

판정: 총점 ≥ 13/16 **그리고** §3.1 태그가 문서당 ≤2건이면 합격. 아니면 진단 붙여 ③으로 반송. **자기 채점 함정 주의** — 검증 패스는 재작성 패스가 "고쳤다"는 말을 믿지 말고 원문 대비 실제 텍스트를 다시 카운트한다.
